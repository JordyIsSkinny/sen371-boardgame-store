# Design System — Tokens

Source of truth for the values in `client/src/index.css`'s `@theme` block
(Tailwind v4, CSS-first — there is no `tailwind.config.js`). Committed here
so the values are checkable against something, not just the token file's own
comments. Where a value came from the Figma design system export directly,
it's marked **given**; where it was generated to fill a gap Figma didn't
specify, it's marked **generated**, with the method.

## Colour

### Primary — indigo

| Token | Hex | Source |
|---|---|---|
| `primary-100` | `#E6E4F5` | given |
| `primary-200` | `#B7B2DE` | generated — HSL midpoint of 100/300 |
| `primary-300` | `#8A83C4` | given |
| `primary-400` | `#6259AC` | generated — HSL midpoint of 300/500 |
| `primary-500` | `#4A4380` | given |
| `primary-600` | `#3C3669` | generated — HSL midpoint of 500/700 |
| `primary-700` | `#2E2A52` | given |
| `primary-800` | `#252141` | generated — HSL midpoint of 700/900 |
| `primary-900` | `#1B1830` | given |

Figma's own scale is five stops (100/300/500/700/900), not the ten-stop
50-900 Tailwind convention — there is no `primary-50`. All five given stops
share the same ~247° hue, so 200/400/600/800 are generated by blending in
HSL space between their two real neighbours, keeping every step on-family
rather than drifting through unrelated colours.

The generated 200/400/600/800 stops (both primary and neutral) are not
defined in Figma at all — not even as an unused variable — so they carry no
design sign-off, only the HSL-midpoint interpolation above. They are
already in live use (`text-primary-600` in `Catalogue.jsx`'s remove-chip
button and in `ProductDetail.jsx`'s breadcrumb link; `accent-primary-600`
on `Catalogue.jsx`'s checkboxes), so they are being kept rather than
removed — deleting them would silently drop those utilities in Tailwind v4
(no build error, the class just renders nothing). Treat them as
provisional: fine to keep shipping, but worth a design check before
reaching for one again in new work.

### Accent — amber

| Token | Hex | Source |
|---|---|---|
| `accent` | `#E8A33D` | given |

One value, not a scale. **Surface colour only** — button and badge
backgrounds, never text on a light background: Figma's own export states
2.1:1 against a light background, well under the 4.5:1 minimum for normal
text (independently checked here: ~2:1). Dark text (`primary-900`) on an
amber surface passes comfortably (~8:1).

### Semantic — status colours

| Token | Hex | Source |
|---|---|---|
| `success` | `#2E7D5B` | given |
| `warning` | `#C77A20` | given |
| `error` | `#C0392B` | given |

All three are real bound Figma variables (`get_variable_defs`), not
literals — confirmed on Input's error-state border, StockBadge's in-stock
and low-stock text, and ProductCard's in-stock badge. There is no `info`
variable anywhere in the current component set (checked across every
component below plus NavBar); it's intentionally not defined here rather
than guessed — add it only once a real component actually binds one.

Note StockBadge's out-of-stock state does **not** use `error` — it uses
`neutral-700`. Out of stock isn't a fault state in this design, so don't
assume `error` is the right token for it.

### StockBadge tints

| Token | Hex | Source |
|---|---|---|
| `success-tint` | `#E5F0EC` | generated |
| `warning-tint` | `#F8EEDF` | generated |
| `neutral-tint` | `#E7E5E1` | generated |

These are StockBadge's pill background colours (in-stock / low-stock /
out-of-stock respectively). Marked **generated** rather than **given**
because they aren't Figma variables at all, unlike everything else on this
page — binding a variable and then setting opacity on it didn't hold in
the Figma Plugin API, so the tints ended up as literal hex fills on the
StockBadge component instead. Read directly off StockBadge (node 66:27)
via `get_design_context` and named here so nothing downstream has to
reinvent them from a screenshot.

## Spacing

4px base. No custom token needed: Tailwind v4's default `--spacing` is
already `0.25rem` (4px), and Figma's own spacing scale (4, 8, 12, 16, 24,
32, 48, 64, 96) maps exactly onto Tailwind's default numeric scale at those
values.

## Radius

Named by role rather than size, matching how the design system states it.

## Provenance

- **Primary, neutral, accent, type scale, radius**: Figma design system
  export (screenshots, reviewed 2026-09-09).
- **Semantic colours, StockBadge tints**: pulled live from the Figma file
  (`get_variable_defs` and `get_design_context` via the Figma MCP,
  file `9jaB1VepWpkM3Anp6xI4V5`, Components page, 2026-09-10) rather than
  from screenshots — checkable by re-running the same calls against the
  same node IDs, not just by eyeballing an export.

If a value here and the live Figma file ever disagree, Figma wins — update
this doc and `client/src/index.css` to match, not the other way around.
